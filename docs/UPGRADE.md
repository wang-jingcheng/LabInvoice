# 升级、备份和回滚

## 升级前备份

停掉应用的所有 worker，等正在处理的上传结束后，再备份数据库和文件。以下命令在新版代码的根目录运行，路径替换为你的数据目录与备份位置。

```bash
python scripts/backup_data.py --data-dir /path/to/labinvoice-data --output-dir /path/to/backups
```

脚本通过 SQLite backup API 生成数据库快照，把 `labinvoice.db` 和 `uploads/` 打包，并重新读取 ZIP 核验文件哈希。另存现有的 `.trash/`、本地部署配置和显式设置的环境变量，生产备份宜有站外副本。

若是从早期版本迁移，可以把备份和原数据目录交给离线校验脚本。它在临时副本中执行迁移，并核对历史表、上传文件和原批次总额。若当前数据已做项目级金额校准，另以实际的校准后金额和项目汇总做对照。

```bash
python scripts/check_upgrade.py --data-dir /path/to/labinvoice-data --backup /path/to/backups/backup.zip
```

## 升级并检查

1. 更新程序文件，安装新版依赖。为 `LABINVOICE_DATA_DIR` 指向原数据库和上传目录所在的位置。省略此项时，默认使用 `app.py` 所在目录。
2. 显式设置 `LABINVOICE_ADMIN_PASSWORD` 再启动服务。新开源版本依赖此变量启用管理员登录。使用过旧默认密码的实例应改用新密码。
3. 启动会运行增量数据库迁移。需要升级旧表结构时，应用会在数据目录 `.backups/` 留存迁移前快照。
4. 用成员和管理员分别登录，抽查旧任务、票据、附件、金额及项目导出。

历史批次只有合计时，系统沿用原合计，并按可识别票面金额比例分摊。整批均无法识别时平均分摊，以分为单位处理尾差。页面将这类历史结果标为待核对。新上传的图片和无文本层 PDF 需要手动填写金额。

票据归类记录在数据库中，原件和原始元数据继续存放在原目录。成员删除账户后保留历史归属，旧姓名目录也继续可读。

## 回滚

停服后，给当前数据做一份独立备份。保留升级后新增的记录与上传文件，再在隔离目录解压升级前备份并核验。确认恢复范围后，将旧程序与匹配的数据快照一同切换，并复查登录、历史任务和导出。

若旧实例曾使用固定会话密钥，请更换 `LABINVOICE_SECRET_KEY` 并让成员重新登录。
